## Arquitectura

Se conserva catálogo → descubrimiento → repositorio → `CatalogViewModel` → `StateFlow`.
No se añaden módulos ni dependencias de aplicación. La compilación mantiene Java 17;
los tests usan un launcher Java 21 porque Robolectric API 36 lo exige. CI prepara ambos
JDK y Gradle detecta Java 21 mediante `JAVA_HOME_21_X64` cuando sea necesario.
El test existente de fecha localizada normaliza únicamente espacios no separables
introducidos por CLDR en Java 21 antes de comprobar `6:00 PM`; no cambia el formato
ni el comportamiento del producto y conserva la comprobación de fecha, hora y DST.

La validación local usa `tools/unsigned-validation.gradle` para ensamblar sin crear
la clave Debug automática de AGP. Este init script no cambia los identificadores ni
la configuración habitual de firma del proyecto. `verify_rs04_apks.py --unsigned-debug`
comprueba las mismas identidades, SDK, FileProvider, alineación y hashes, exigiendo que
ambos APK estén sin firma.

Tras la corrección de auditoría, CI recupera el flujo RS-04 exclusivamente para PR
internas de `robdor80/RobStore`: omite ese init script, genera el APK Debug firmado
mediante la clave temporal habitual de desarrollo de Android y ejecuta el verificador
en su modo original, que exige firma Debug válida y Release sin firmar. Las ejecuciones
por push y las PR desde forks mantienen ambos APK sin firma y no suben un DEV instalable.
Se conservan los tests y lint de ambas variantes, Java 21 para Robolectric API 36 y
Java 17 para Gradle/compilación.

Sólo tras superar las comprobaciones se sube `robstore-dev-<SHA completo del HEAD>`
como artefacto de trabajo de GitHub Actions, con retención de 30 días y descarga
autenticada, sin crear una Release. Contiene únicamente el APK `RobStore-DEV-<SHA de
12 caracteres>.apk`, `SHA256SUMS`, el certificado público en `firma-debug.txt` y el
informe `verificacion.md`. No se versionan ni suben claves privadas, keystores ni
contraseñas. El repositorio es público; este artefacto no sustituye una distribución
Release ni constituye una garantía de confidencialidad para los colaboradores con acceso.

La firma temporal de CI puede variar entre ejecuciones. No se garantiza que un APK DEV
actualice otro generado en una ejecución anterior; si Android rechaza la actualización
por firma distinta, será necesario desinstalar la DEV anterior, con la pérdida de sus
datos locales. La persistencia de la firma de desarrollo se resolverá en **P04**.

- `InstalledApplications` permite sustituir la consulta Android por dobles.
- `AndroidInstalledApplications` consulta `getPackageInfo` únicamente para cada paquete
  identificado en el catálogo. Usa flags tipados desde API 33, `longVersionCode` desde
  API 28 y `versionCode.toLong()` en API 26–27.
- `InstalledApplication` conserva paquete, código `Long?`, nombre y resultado de consulta
  LAUNCHER (componente disponible, no disponible o consulta desconocida). Un código no
  positivo se trata como ilegible, conservando la observación de instalación.
- `CatalogInventory` deduplica paquetes, consulta en `Dispatchers.IO` y serializa las
  consultas con un mutex. Publica un mapa por ID de repositorio, en memoria. No enumera
  ni persiste inventarios de otras aplicaciones; tampoco escribe observaciones locales
  en la caché del catálogo. El mapa inicial vacío representa consultas aún pendientes.
- `CatalogApplicationStatus` separa el `CatalogApp` publicado, `InstallationQuery` local
  y `VersionComparison`. `CatalogViewModel.installedState` deja esta API lista para P02.

`MainActivity` solicita una reconsulta en `ON_RESUME`; el ViewModel también reconsulta
al cambiar las aplicaciones del catálogo y al recibir el retorno del instalador.
Estas rutas no llaman a `repository.refresh()`, no invalidan TTL ni hacen peticiones
GitHub. Dos eventos próximos (callback y resume) pueden producir dos consultas locales;
no hay comprobaciones periódicas. El retorno del instalador conserva el estado RS-04
`UNCONFIRMED`; sólo una nueva observación del PackageManager aporta información local.

## Visibilidad Android y límites

`<queries>` declara exclusivamente `ACTION_MAIN` + `CATEGORY_LAUNCHER`, sin paquetes
estáticos ni `QUERY_ALL_PACKAGES`. La resolución LAUNCHER se restringe con `setPackage`
al paquete consultado; se conserva un componente exportado, habilitado y sin permiso
requerido. La disponibilidad es una observación puntual: no garantiza que una apertura
posterior tenga éxito, ni se añade apertura de apps en P01.

`InstallationQuery` distingue:

- `Installed`: Android permite leer el paquete. Incluye apps visibles sin LAUNCHER.
- `Absent`: `NameNotFoundException` en API 26–29, donde no se aplica el filtrado de
  visibilidad introducido en Android 11.
- `Unknown`: paquete no encontrado en API 30+, fallo de seguridad u otro fallo de consulta.

La ausencia de resultados LAUNCHER **no** confirma ausencia del paquete. En Android 11+
una app sin LAUNCHER puede quedar oculta salvo que Android conceda visibilidad por otra
relación. Incluso una consulta LAUNCHER vacía puede corresponder a componentes deshabilitados.
No se promete detectar todas las aplicaciones instaladas. La observación sólo corresponde
al usuario/perfil de RobStore; no cubre otros perfiles ni instalaciones archivadas como
instalaciones ejecutables. Las restricciones de fabricante/administración requieren
validación física; Robolectric no reproduce integralmente el filtrado real.

## Manifiesto v1 y caché

Se mantiene `schemaVersion = 1`. Campos nuevos opcionales e independientes:

```json
"versionCode": 42,
"versionName": "1.2.0"
```

`versionCode`: token entero JSON entre 1 y `9223372036854775807`. Se rechazan cadenas,
fracciones, exponentes, booleanos, null y desbordamientos. `versionName`: cadena no vacía
ni sólo espacios, máximo 120 unidades UTF-16, sin caracteres de control; no se utiliza
para ordenar versiones. Si un campo no existe se conserva `null`; null explícito en el
manifiesto es inválido. Las validaciones se aplican también al cargar metadatos de caché.

Los campos viven en `CatalogRelease` con valores por defecto `null`, por lo que los JSON
antiguos de `catalog-v1.json` se deserializan conservando el catálogo completo. La caché
nueva conserva ambos campos sin migración destructiva. No cambia el nombre ni el esquema
de la caché. La serialización interna admite null para representar metadatos desconocidos.

El descubrimiento copia versiones del mismo `robstore.json` obtenido con `ref=tag` de la
Release estable seleccionada. No consulta `main`. No cambia la selección por fecha de
publicación e ID ni el tratamiento de drafts/prereleases. No infiere códigos mediante
SemVer, tag o nombre de versión. Se prueba el manifiesto real sin versiones de
[Cuadrante_App v1.0.0](https://github.com/robdor80/Cuadrante_App/blob/v1.0.0/robstore.json),
copiado como fixture de sólo lectura en RobStore.

## Comparación

Se comparan directamente códigos `Long`, sin restas que puedan desbordar:
`PUBLISHED_NEWER`, `SAME`, `PUBLISHED_OLDER`. Se conservan estados separados
`PUBLISHED_UNKNOWN`, `INSTALLED_VERSION_UNREADABLE`, `INSTALLATION_UNKNOWN`, `ABSENT`.
La incertidumbre de instalación tiene prioridad; para un paquete instalado, un código
local ilegible tiene prioridad sobre el código remoto desconocido. La información
publicada y local original permanece disponible para que P02 pueda mostrar ambos motivos.

## Riesgos y decisiones para P02

Definir con RobStyle cómo presentar desconocido, ilegible, ausencia y versiones remotas
anteriores sin inducir instalaciones o downgrades. Los metadatos publicados son declaraciones
del autor, no prueba criptográfica del APK ni de su firma; las verificaciones RS-04 se
mantienen. P02 deberá manejar cambios de estado entre consulta y acción y el mapa todavía
pendiente. No se ha implementado autoactualización.

Quedan pruebas físicas de visibilidad en API 30–36 (incluido fabricante), apps sin LAUNCHER,
componentes deshabilitados, perfiles gestionados, cancelación/éxito real del instalador y
reanudar tras terminar el proceso. No se han instalado apps ni utilizado dispositivos físicos.
No se han modificado otros repositorios, publicado Releases ni realizado fusiones.
