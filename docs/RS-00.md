# RS-00 — Fundaciones

## Inspección y alcance

El repositorio `robdor80/RobStore` contenía únicamente `README.md` en
`f7f02da1932ccb7913f1d165570a908191d51ebc` (`Initial commit`). La rama local inicial
era `work`; `git ls-remote --symref origin HEAD` y GitHub confirmaron `main` como
rama por defecto, con ese mismo HEAD. No había instrucciones `AGENTS.md` ni trabajo
local pendiente. Se creó `codex/rs-00-fundaciones` antes de modificar archivos.

La fase entrega una base Android, sin permisos de red ni instalación, clientes
GitHub, catálogo, descargas, WorkManager, autenticación o lógica de tienda.

## Decisiones y versiones

| Elemento | Selección |
| --- | --- |
| JDK | 17; validación Cloud con Temurin 17.0.21+9 |
| Gradle / DSL | Wrapper 8.13 / Kotlin DSL |
| Android Gradle Plugin | 8.13.2 |
| Kotlin y plugin Compose | 2.2.21 |
| Compose BOM | 2025.12.00 (UI 1.10.0; Material 3 1.4.0) |
| Activity Compose | 1.12.2 |
| JUnit / Robolectric | 4.13.2 / 4.16.1 |
| SDK | compile 36 / target 36 / min 26 |
| Herramientas SDK usadas | Command-line Tools 19.0; Build Tools 35.0.0; Platform Tools 37.0.1 |

Son versiones estables compatibles; AGP 8.13.2 admite API 36 con Gradle 8.13 y
JDK 17. Build Tools 35.0.0 es la versión predeterminada de este AGP y no reduce
`compileSdk` ni `targetSdk`. Las dependencias están centralizadas en
`gradle/libs.versions.toml`; no se usan versiones dinámicas.

Un único módulo `app`, Activity delgada, entrada Compose y paquete `ui/robstyle`.
La pantalla recibe el nombre desde recursos de variante. No necesita estado ni
navegación: ViewModel + StateFlow, sus dependencias y rutas se añadirán cuando
exista una necesidad real. No se crean interfaces, repositorios o capas vacías.

RobStyle centraliza esquemas claro/oscuro, tipografía, formas y dimensiones.
Los valores base de Material 3 son provisionales; no constituyen la identidad
RobStyle aprobada. RS-01 debe contrastarla con RobGit y proporcionar los iconos.
Los iconos adaptativos normal/redondo tienen recursos superpuestos en `src/debug`,
con una D provisional que RS-01 puede reemplazar sin cambiar el manifiesto.

Release no tiene firma privada configurada y genera un APK sin firmar. Debug
utiliza la firma estándar automática de desarrollo del SDK, local e ignorada.
No se proporciona ni versiona material de firma, contraseñas o tokens.

## Entorno Cloud y reproducción

La inspección encontró Java 21 de sistema, sin JDK 17, Gradle global, Android SDK
ni variables Android configuradas. No se necesitó Android Studio. Todas las
herramientas descargadas, cachés, temporales y configuración del entorno se
ubicaron en `.cloud/`, ignorado por Git, dentro de este repositorio.

Fuentes oficiales utilizadas:

- Temurin: `https://github.com/adoptium/temurin17-binaries/releases/download/jdk-17.0.21%2B9/OpenJDK17U-jdk_x64_linux_hotspot_17.0.21_9.tar.gz`, SHA-256 `8b9b611d917e3dfd8419d3566b5949226f69b052fed7e109c1368add1dfe8711`, verificado contra el fichero `.sha256.txt` de la misma release.
- SDK: `https://dl.google.com/android/repository/commandlinetools-linux-13114758_latest.zip`, SHA-1 del índice oficial `5fdcc763663eefb86a5b8879697aa6088b041e70`.
- Gradle: `https://services.gradle.org/distributions/gradle-8.13-bin.zip`, SHA-256 `20f1b1176237254a6fc204d8434196fa11a4cfb387567519c61556e8710aed78`.
- El JAR del Wrapper también coincide con el SHA-256 oficial `81a82aaea5abcc8ff68b3dfcb58b3c3c429378efd98e7433460610fecd7ae45f`.

Para reconstruir el entorno Linux sin herramientas previas, descarga y verifica
estos archivos con `curl` y `sha256sum`/`sha1sum`; extrae el JDK en
`.cloud/jdk-17.0.21+9` y las Command-line Tools en
`.cloud/sdk/cmdline-tools/19.0`. Gradle global no es necesario: el Wrapper incluido
obtiene y verifica su propia distribución. Desde la raíz:

```sh
mkdir -p .cloud/home .cloud/tmp .cloud/android-user .cloud/gradle
export JAVA_HOME="$PWD/.cloud/jdk-17.0.21+9"
export ANDROID_HOME="$PWD/.cloud/sdk"
export ANDROID_USER_HOME="$PWD/.cloud/android-user"
export GRADLE_USER_HOME="$PWD/.cloud/gradle"
export TMPDIR="$PWD/.cloud/tmp"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/19.0/bin:$PATH"
export JAVA_TOOL_OPTIONS="-Duser.home=$PWD/.cloud/home -Djava.io.tmpdir=$TMPDIR"
sdkmanager --sdk_root="$ANDROID_HOME" --licenses
sdkmanager --sdk_root="$ANDROID_HOME" 'platforms;android-36' 'build-tools;35.0.0'
./gradlew --version
./gradlew clean
./gradlew test
./gradlew assembleDebug
./gradlew assembleRelease
./gradlew lint
```

En este Cloud el acceso a red pasa por el proxy del entorno. Se conservaron sus
variables y la verificación TLS. Java necesitó el almacén de confianza del sistema
`-Djavax.net.ssl.trustStore=/etc/ssl/certs/java/cacerts` y las propiedades
`http.proxyHost`, `http.proxyPort`, `https.proxyHost`, `https.proxyPort` derivadas
de `HTTPS_PROXY`. Se añadieron a `JAVA_TOOL_OPTIONS` para que las hereden también
los procesos de tests de Robolectric. `sdkmanager` utilizó
`--proxy=http --proxy_host=proxy --proxy_port=8080`.
Esta configuración es local, no una exigencia del proyecto ni de GitHub Actions.

Para limitar recursos locales, `.cloud/gradle/gradle.properties` contiene
`org.gradle.workers.max=2` y `kotlin.compiler.execution.strategy=in-process`.
No se modificaron herramientas ni configuraciones fuera del repositorio.

## Validación

En Cloud, el 29 de octubre de 2026, con JDK 17 y Android SDK 36:

| Comando | Resultado |
| --- | --- |
| `./gradlew --version` | PASS: Gradle 8.13, JVM 17.0.21 |
| `./gradlew clean` | PASS |
| `./gradlew test` | PASS: 3 pruebas Debug + 3 Release, sin fallos ni omisiones |
| `./gradlew assembleDebug` | PASS |
| `./gradlew assembleRelease` | PASS: APK sin firmar |
| `./gradlew lint` | PASS: 0 errores; 3 avisos `NewerVersionAvailable` |

Se repitieron `clean` y `test assembleDebug assembleRelease lint` tras la revisión
final de recursos; todos terminaron correctamente con las fuentes de esta entrega.
Lint solo sugiere actualizar los dos plugins Kotlin a 2.4.21 y Robolectric a 4.17.
Se mantiene el conjunto estable fijado y validado de RS-00. No se han desactivado
comprobaciones de lint; los avisos de recursos, iconos y extracción de datos están
corregidos. Las reglas del manifiesto deshabilitan copias y transferencias de datos.

Las pruebas de Robolectric se ejecutan explícitamente sobre API 28. Comprueban
los IDs y nombres instalables de ambas variantes, el sufijo de versión DEV, la
resolución de la Activity launcher y su arranque con un contenedor Compose.
Robolectric 4.16.1 avisa al descubrir SDKs de que API 36 requiere Java 21;
no se solicita ese runtime en estas pruebas y se mantiene JDK 17 según el alcance.
AGP también avisa de que empaqueta `libandroidx.graphics.path.so` sin realizar
stripping adicional. Es una dependencia transitiva de AndroidX; `file` confirma
que sus cuatro binarios ya llegan como `stripped`. No hay código nativo propio
ni se necesita instalar el NDK para esta fase.
No se ha realizado prueba visual en emulador o dispositivo, ni prueba de runtime
sobre API 36. Esto no reduce el SDK de compilación ni el SDK objetivo.

La inspección de los APK con `aapt` confirma las dos identidades, los nombres
visibles, `0.1.0-DEV`/`0.1.0`, `minSdk = 26`, `targetSdk = 36` y compilación con
API 36. También confirma que no se han añadido permisos de Internet ni instalación.
Los recursos de icono empaquetados son distintos y el DEV contiene la D provisional.
`apksigner verify` acepta Debug y confirma la ausencia de firma en Release;
`zipalign -c -P 16 4` pasa para ambos APK.

La CI instala JDK 17 y el SDK y ejecuta `test lint assembleDebug assembleRelease`.
Solo tiene permisos de lectura; no publica APK, Releases ni firmas.
Se fija Ubuntu 24.04 y se usan acciones estables con Node 24: checkout 7.0.1,
setup-java 6.1.0, setup-android 4.0.4 y setup-gradle 6.4.1. El SDK utiliza las
mismas Command-line Tools 19.0 de Cloud (`13114758`), con `platform-tools`
explícito. Esto evita el paquete antiguo `tools`, retirado del índice de Google,
que provocó el fallo de preparación de la primera ejecución remota.
