# RS-03 — Experiencia visual y catálogo RobStyle

## Objetivo y alcance

Convertir el catálogo automático de RS-02 en una experiencia de tienda Android.
Base verificada: `main`, `08a07b96e8fd3eff4a0c3597d914a0735f0604b1`.
Rama: `codex/rs-03-ux-visual-robstyle`. Entrega mediante PR Draft para auditoría,
sin merge.

Se conserva el descubrimiento real, selección de Releases estables, contrato
`robstore.json`, APK exacto, persistencia, cuotas y funcionamiento offline-first.
No cambian SDK, dependencias, permisos, identificadores, versiones ni launcher.

## Decisiones visuales y componentes

- Home: barra compacta con nombre de variante, refresco accesible y Ajustes.
  El progreso aparece en la propia barra incluso al desplazar el catálogo.
- `RobCatalogGrid`: `LazyVerticalGrid` con `GridCells.Adaptive`, claves estables
  `repositoryId` y elementos virtualizados. Anchura mínima 136 dp multiplicada
  por `max(1, fontScale)`, márgenes de 16 dp y separaciones de 16 dp.
  A 320 dp y fuente normal caben dos columnas; a 600 dp, tres. El contenido
  está centrado y limitado a 1000 dp; a 1200 dp caben seis columnas. Al 200 %
  de fuente, 320 dp usa una sola columna. El número depende del ancho disponible.
- `RobAppTile`: icono de 80 dp, nombre de dos líneas con elipsis y versión de una
  línea con elipsis. Toda la superficie es pulsable mediante la Card de Material.
  No incluye descripciones, URLs, GitHub ni controles de instalación.
- `AppIcon`: reutiliza `CatalogIconLoader` sin modificarlo, con límites y cachés
  de memoria/disco de RS-02. Mantiene las mismas dimensiones durante la carga,
  éxito y fallback. El símbolo de malla y su descripción accesible identifican
  expresamente una sustitución, en lugar de fingir que es el icono oficial.
- `RobDetailHeader`: icono de 104 dp, nombre, versión y publicación. Disposición
  vertical que permite nombres y versiones largos sin competir con el icono.
  Área reservada a futuras acciones con instalación deshabilitada y texto explícito.
- `RobInfoSection`: secciones para descripción, novedades e información del APK,
  con texto seleccionable. Las notas son texto plano y conservan saltos de línea;
  no hay Markdown activo, HTML, WebView ni recursos externos.
- Detalle: paquete, repositorio oficial, URL, nombre y tamaño legible del APK,
  URL como metadato, SHA-256 cuando existe y aviso de ausencia de verificación
  local de integridad/firma. Ninguna URL inicia descarga o instalación.
- Ajustes: origen (propietario, topic, canal), sincronización y diagnósticos.
  Conserva mensajes técnicos y repositorios excluidos, con desplazamiento vertical.
- Paleta RobStyle conservada: fondo `#070D18`, superficies azuladas, cian
  `#69DCFF`, texto claro, bordes discretos y formas suaves. La barra aumenta su
  altura al ampliar fuente para admitir el título y las acciones accesibles.

## Estados y navegación

Sin instantánea, la carga inicial muestra progreso y una explicación breve,
separada del estado vacío real. El error inicial ofrece reintento mediante el
callback real. Con instantánea, nunca se sustituye el catálogo por una carga o
un error: también se conserva una instantánea válida de cero aplicaciones.
La caché desactualizada y el fallo se indican de forma secundaria. Los datos
siguen disponibles sin conexión.

Durante carga/refresco, la acción está deshabilitada y el callback protegido.
Antes de la hora permitida, el repositorio conserva sus reglas y comunica el
aplazamiento. Home muestra una explicación breve y la próxima hora local; los
detalles técnicos permanecen en Ajustes. No hay temporizadores ni sondeos.

Las rutas siguen usando `repositoryId`, con retorno por barra y Atrás de Android.
Si desaparece la app de la instantánea, la ficha muestra un mensaje informativo.
No se inventan apps: todos los fixtures están en tests o en funciones privadas
exclusivas de previews, sin referencias desde las pantallas de producción.

## Fechas

`CatalogFormatting.kt` centraliza fechas locales con `ZoneId.systemDefault()` y
`Locale.getDefault()`, fecha localizada de longitud media y hora corta,
separadas por ` · `. Por ejemplo, en español: `29 oct 2026 · 22:36`.
La hora permitida procede de `CatalogState.nextRefreshAt`; no se extrae del
mensaje ni se aplican sustituciones o expresiones regulares. Valores cero o
negativos y fechas de Release inválidas se omiten.

El único cambio de producción fuera de presentación es retirar el timestamp ISO
incrustado en el mensaje de cooldown de `CatalogRepository`. Se mantienen sus
cálculos, límites, estados y contratos. Tests cubren UTC, Europe/Madrid en
invierno/verano, transición de horario de verano, cambio de día y locale US.

## Pruebas y compilación

La suite ampliada ejecuta **178 pruebas (89 Debug + 89 Release)**, sin fallos,
errores ni omisiones. Validación sobre las fuentes finales:

| Comando | Resultado |
| --- | --- |
| `./gradlew test --no-daemon` | Correcto, 178 pruebas; 53 s |
| `./gradlew lint --no-daemon` | Correcto, cero errores y siete avisos heredados; 57 s |
| `./gradlew assembleDebug --no-daemon` | Correcto; 1 min 26 s |
| `./gradlew assembleRelease --no-daemon` | Correcto; 1 min 30 s |
| `git diff --check` | Correcto |

Los siete avisos son únicamente `NewerVersionAvailable` para dependencias ya
existentes. No se añaden exclusiones ni se cambian versiones. Continúa el aviso
heredado de empaquetado de `libandroidx.graphics.path.so` sin stripping adicional.
El caso de imagen inválida puede registrar `Failed to create image decoder ...
unimplemented`, como RS-02; sus aserciones pasan y no se oculta el caso.

APK: `app/build/outputs/apk/debug/app-debug.apk` y
`app/build/outputs/apk/release/app-release-unsigned.apk`. Los informes de tests y
lint quedan en `app/build/reports/`. El workflow Android se conserva y vuelve a
validar pruebas, lint y ambas compilaciones al publicar la rama/PR.

Las expectativas anteriores cambian por motivos visibles: refresco pasa de botón
con texto a acción con descripción semántica, el vacío dice «publicadas» y el
tamaño usa KiB/MiB. Los desplazamientos buscan semántica en contenedores perezosos,
sin índices fijos de listado. Se conservan los tests anteriores.

Los fixtures usan transporte HTTP simulado. Ningún test consulta GitHub real ni
descarga APK. Se amplían escenarios de tamaño/fuente/textos largos, navegación,
Atrás de Android, app desaparecida, iconos, estados y fechas. Las pruebas de
identidad y launcher de ambas variantes se conservan.

Para regenerar las capturas sin emulador:

```sh
./gradlew testDebugUnitTest --tests '*RobUiTest.*' --rerun-tasks --no-daemon
```

Se generan en `app/build/rs03-evidence/debug/`; la suite Release genera su propia
carpeta `release/`. El exportador pertenece exclusivamente al código de test.

El entorno no dispone de emulador, dispositivo conectado ni renderizador
interactivo de Compose Previews. La captura estándar `captureToImage` no recibe
respuesta de PixelCopy en este runner; por ello se usa el dibujo nativo de la
vista. El resultado no certifica GPU, barras del sistema, densidades físicas,
interacción táctil o TalkBack. La revisión en Android real continúa pendiente.

### Comprobación reproducible en Android real

1. Compilar `./gradlew assembleDebug --no-daemon` e instalar
   `app/build/outputs/apk/debug/app-debug.apk` mediante Android Studio o
   `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
2. Abrir RobStore DEV con conexión. Confirmar iconos oficiales cuando existan,
   fallback distinto, nombres/etiquetas legibles y malla desde el primer vistazo.
   No publicar apps ficticias para realizar esta comprobación.
3. Probar ancho compacto, horizontal y tableta o ventana redimensionable. En
   Android Studio abrir las previews citadas para los escenarios deterministas.
4. En Ajustes de Android ampliar fuente al máximo (incluido 200 % donde se
   permita). Comprobar ausencia de solapamientos, texto truncado con elipsis en
   celdas, título de variante, áreas táctiles y detalle/Ajustes desplazables.
5. Abrir una app, leer las secciones y volver tanto con la flecha como con el
   gesto/botón Atrás. Comprobar que instalar está deshabilitado y no hay versión
   instalada ni descarga al tocar metadatos.
6. Refrescar: comprobar progreso sin desaparición del catálogo. Repetir antes de
   cinco minutos: explicación de aplazamiento con próxima hora local. Cambiar
   zona horaria/idioma y reabrir la Activity para comprobar fechas locales.
7. Cerrar y reabrir sin conexión con caché existente. Verificar catálogo conservado
   (incluso vacío), aviso de fallo/caché y diagnósticos en Ajustes. Para primer
   arranque sin caché, usar una instalación limpia DEV sin conexión y reintentar
   respetando el intervalo; no borrar datos personales de otra variante.
8. Revisar con TalkBack títulos, nombres, iconos/fallback, refresco y navegación.
   Guardar capturas de Home, detalle, fuente ampliada y offline para la auditoría.

privada configurada. La PR debe permanecer Draft y sin fusionar hasta la auditoría.
