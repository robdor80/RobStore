## Estados y acciones

Home mantiene navegación por tarjeta, malla adaptable, iconos y RobStyle, y añade
una indicación textual discreta y la versión local observada (nombre y código);
si no consta instalada, conserva la etiqueta publicada. AppDetail añade el estado y las versiones
instalada/publicada, con nombre informativo y `versionCode` explícito.

| Observación | Presentación | Acción inicial en detalle |
| --- | --- | --- |
| Instalada, mismo código | Instalada y actualizada | Abrir si tiene LAUNCHER accesible |
| Código publicado mayor | Actualización disponible | Actualizar; Abrir si procede |
| Código instalado mayor | Versión instalada superior a la publicada | Abrir si procede |
| Ausencia confirmada | Aplicación no instalada | Instalar |
| Visibilidad restringida | Instalación desconocida por Android | Descarga voluntaria con explicación |
| Sin código remoto | Versión remota desconocida; actualización no demostrada | Descarga voluntaria; Abrir si procede |
| Código local ilegible | Instalada; versión local ilegible | Descarga voluntaria; Abrir si procede |
| Sin observación correspondiente al catálogo actual | Consulta local pendiente | Descarga voluntaria con explicación |

No se deduce ausencia a partir de restricciones de Android. Sólo `versionCode`
determina actualizaciones; etiquetas, SemVer y `versionName` nunca deciden.
La observación se acepta para mostrar estados sólo si corresponde a la entrada
actual del catálogo. No se persiste un inventario general ni se solicita
`QUERY_ALL_PACKAGES`.

Instalar/Actualizar inicia la descarga explícita; las confirmaciones RS-04 y la
acción posterior de entregar el APK al instalador siguen siendo necesarias.
Los paquetes de ambas identidades de RobStore se excluyen de descarga/instalación
en este flujo. No se abre ninguna aplicación automáticamente.

Abrir usa `Intent.makeMainActivity` con una actividad MAIN/LAUNCHER accesible,
exportada, habilitada y sin permiso requerido, obtenida por las APIs oficiales.
Se vuelve a consultar en cada pulsación. La actividad se lanza en el hilo principal;
los errores de disponibilidad, seguridad o argumentos muestran un mensaje y se
actualiza el inventario local. Una aplicación sin LAUNCHER conserva su estado de
instalación y versión, sin botón Abrir.

## Descarga e instalación

Se reutilizan `DownloadCoordinator`, `PreparedApk`/`ApkVerifier`, `DownloadFiles`,
`BinaryClient` y `AndroidInstaller`. No hay un segundo motor.
Se conservan revalidación de origen/Release, HTTPS, tamaños, SHA-256 cuando existe,
paquete, rutas privadas, FileProvider de sólo lectura, caducidad, rehash, cancelación,
limpieza, reintento y confirmaciones interactivas de Android.

Si el manifiesto declara `versionCode`, debe coincidir exactamente con el leído del
APK. La discrepancia impide publicar el archivo preparado y elimina el parcial.
La comprobación también se repite al preparar la instalación. Los manifiestos
antiguos sin código siguen permitiendo descarga voluntaria sin anunciar actualizaciones.

Después de revalidar archivo y catálogo, se consulta de nuevo la versión instalada.
Si supera el código interno del APK, se bloquea la entrega y se elimina el archivo.
Esto incluye instalaciones externas durante la descarga y APK de manifiestos antiguos.
El catálogo se comprueba otra vez al pasar al hilo principal, antes de permiso/entrega,
para detectar cambios mientras se hacía la consulta local. No se fuerza una consulta
GitHub adicional en ese paso. La acción de instalar también refresca el inventario visible: un bloqueo previo
al instalador no deja la versión mostrada obsoleta. El estado desconocido se mantiene como tal; Android
aplica la última comprobación de versión y firma, incluidos cambios posteriores a
nuestra consulta local. No puede eliminarse esa carrera entre procesos desde RobStore.

El parseo de un APK y el digest declarado por GitHub no son prueba criptográfica de
la identidad de firma. La interfaz lo explica y no garantiza conservación de datos
con certificados incompatibles. No hay desinstalación ni modificación silenciosa.

## Retorno y navegación

P01 ya reconsulta el inventario al reanudar y volver del instalador; P02 conecta ese
flujo con Home y AppDetail. Se muestra lo que Android realmente devuelve, sin tráfico
GitHub adicional ni comprobaciones periódicas. El retorno conserva `UNCONFIRMED`,
SHA local e información de descarga; no acredita instalación correcta. La versión
local consultada se muestra separadamente. Cancelación, fallo y rechazo por firma
pueden ser indistinguibles mediante ACTION_VIEW; se explica esa limitación.
Los errores de apertura del instalador permiten reintento explícito y nueva verificación.
El ViewModel conserva la descarga durante navegación y recreación de Activity.
